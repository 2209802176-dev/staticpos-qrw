# 版本3飞控接入与记录协议

对应`UserCode.cpp`、`APM_Config.h.fragment`及`core/RobustWindowEstimator.h`。目标为ArduCopter 4.6.3，固定上游提交`92b0cd788ec29406f26c6f9c31d5ceedbd1cc538`，fmuv3、APJ板型ID 9。

算法在飞控内运行，使用GPS实例0与校准后的IMU实例0。输出独立经纬度；原GPS、AHRS/EKF、home、原点和控制目标均不接收该估计器的写入。适用条件是单GPS、未解锁、固定位置及原地转向。

## 传感器与时间

`userhook_MediumLoop`名义10Hz读取`AP::ins().get_gyro(0)`及其健康标志，单位rad/s。读取时的`AP_HAL::micros64()`作为该次IMU样本时间；算法只使用不晚于GPS源历元的IMU记录。未将加速度积分为位置。

每个新的有效`last_fix_time_ms(0)`驱动一次GPS更新。经纬度为整数度×10⁷，水平精度通过`horizontal_accuracy(0, value)`读取，单位米；HDOP由`get_hdop(0)/100`换为无量纲；卫星数来自`num_sats(0)`。质量数据未知时由核心按已确认公式回退。

| 时间量 | 来源与意义 |
|---|---|
| GPS源历元 | `AP_GPS::last_fix_time_ms(0)`，也是固定上游`GPS_RAW_INT.time_usec/1000`的来源 |
| GPS消息时间 | `AP_GPS::last_message_time_ms(0)`；表示消息更新时间，不能未经核对替代源历元 |
| 计算/日志时间 | `AP_HAL::micros64()`，64位启动微秒；逐GPS记录的`TimeUS`是该次处理开始时刻 |
| 快照时间 | 同批NAMED_VALUE的`time_boot_ms`，uint32启动毫秒，表示快照形成时刻 |
| 电脑接收时间 | CSV/JSONL中的单调时钟及UTC，供检查传输、组包和显示行为 |

适配器根据64位当前时间与uint32源时钟的模差重建源微秒时间，处理正常的49.7天毫秒回卷。只有新的有效源历元进入计算；重复包不能增加样本数。飞控重启后显示器应手工断开再连接，以建立新的时间会话。

## 调度与快照

安装脚本启用以下钩子并设置初始预约预算：

| 钩子 | 名义频率 | 初始预算 | 工作 |
|---|---:|---:|---|
| `userhook_MediumLoop` | 10Hz | 500μs | 读取IMU、新GPS计算及机载记录 |
| `userhook_50Hz` | 50Hz | 150μs | 检查有效条件、形成快照，每次最多发送一个字段 |

这些是调度器的预约值，**不是目标板已测最坏执行时间**。`ST_US`只测核心`update_gps()`调用，未包含整个钩子的传感器读取、日志和遥测开销。应结合机载记录及目标板实际负载调整预算。

常态以每1000毫秒形成一批快照为目标；如果上一批尚未完成，先完成上一批。状态变化会抢占未完成快照，创建新批次以尽快传递无效或恢复状态。每批内容形成后保持不变，所有字段共用快照时间戳。有效批次通常25字段，原导航坐标可用时为27字段，在名义50Hz下约0.5～0.54秒完成发送。

每次发送调用上游`send_to_active_channels()`，面向活跃、非private、非高延迟通道。底层逐通道检查单帧发送空间；空间不足可能直接丢失该字段。此接口没有本模块可确认的逐字段重发或完整批次送达保证。分片减少瞬时占用，不能消除拥塞或替代实际链路测试。

## NAMED_VALUE字段

整数通过`NAMED_VALUE_INT`发送，浮点通过`NAMED_VALUE_FLOAT`发送。名称最长10字符。表中uint32计数/时间通过int32位图承载，必要时按`value & 0xffffffff`恢复；经纬度保持有符号整数。

以下12个字段在有效和无效快照中都发送：

| 字段 | 线类型 | 单位/定义 |
|---|---|---|
| `ST_VER` | int32 | 固定3，显示器核对算法代际 |
| `ST_STATE` | int32 | 下表定义的有效状态 |
| `ST_SEQ` | int32/uint32位图 | **快照序号**，每次形成快照自增；不是GPS样本数 |
| `ST_GPSMS` | int32/uint32位图 | 有效时绑定该估计实际使用的GPS源时间；无效时记录当前GPS接口源时间 |
| `ST_MSGMS` | int32/uint32位图 | 有效估计处理时的GPS消息时间；无效时为当前接口值 |
| `ST_COUNT` | int32/uint32位图 | 本次核心会话内推进源时刻的有效GPS历元数，**包含容量损失历元**，不等于成功输出数 |
| `ST_SEG` | int32/uint32位图 | 全局估计段编号；新连续段或重置后首个新段增加 |
| `ST_AGE` | float | 快照形成时源GPS年龄，秒；无有效样本时可为-1 |
| `ST_US` | float | 最近一次核心GPS更新调用耗时，微秒 |
| `ST_MAXUS` | float | 自模块初始化以来的核心更新最大耗时，微秒 |
| `ST_DT` | float | 相邻快照形成间隔，秒；首批为0 |
| `ST_OVR` | int32/uint32位图 | 核心更新耗时超过500μs的累计次数；**不是UART丢包数或完整钩子的调度超时数** |

仅当`ST_STATE=1`时追加以下字段：

| 字段 | 线类型 | 单位/定义 |
|---|---|---|
| `ST_LAT` | int32 | 自研纬度×10⁷ |
| `ST_LON` | int32 | 自研经度×10⁷ |
| `ST_E` | float | 相对本次核心会话首个有效GPS原点的东向位置，米 |
| `ST_N` | float | 相同原点的北向位置，米；E/N均非RTK误差 |
| `ST_NWIN` | int32 | 当前窗口内的观测数 |
| `ST_SIG` | float | 最新GPS观测的基础经验质量尺度σ，米 |
| `ST_LAM` | float | 最新GPS观测的门控倍率λ，1或4 |
| `ST_HUB` | float | 最新GPS观测在最后一轮重加权中使用的Huber因子 |
| `ST_WGT` | float | 最新GPS观测在最后一轮中的归一化权重贡献 |
| `ST_NEFF` | float | Kish权重支持数`(Σw)²/Σw²`，不是独立样本量 |
| `ST_SPAN` | float | 当前窗口最早至最新GPS的跨度，秒，不超过90 |
| `ST_IMU` | int32 | 本次GPS计算所用诊断：0=IMU失效/不够新鲜，1=平稳，2=转向门控 |
| `ST_FCOK` | int32 | 同次快照中AHRS原导航位置接口是否返回位置，0/1 |
| `ST_FCLAT` | int32，可选 | 原导航纬度×10⁷，仅`ST_FCOK=1`时发送 |
| `ST_FCLON` | int32，可选 | 原导航经度×10⁷，仅`ST_FCOK=1`时发送 |

`ST_IMU`及权重绑定最近GPS计算，不能作为所有50Hz发送时刻的即时转动判断。只有最近一个不晚于GPS的IMU样本健康、且距该GPS时刻不超过1秒时，IMU有效诊断才为真。IMU最近样本失效时，先前有效转动样本的2秒保持仍可能有效，此时`ST_IMU=0`、`ST_LAM=4`可以同时出现。σ是经验赋权尺度，非标定协方差。

`ST_FCOK`来自`AHRS::get_location()`，不能单独证明该位置为健康EKF融合解。原导航坐标的时刻为快照形成时刻，与自研位置源GPS历元可能不同。

## 状态与失效规则

| `ST_STATE` | 含义 |
|---:|---|
| 0 | 等待有效GPS，包括无接收器、fix不足及基本输入不合法 |
| 1 | 有效、持续更新；不设置300秒精度里程碑 |
| 3 | GPS接口源时间超过2秒未更新 |
| 4 | 飞控已解锁，静态估计暂停/重置 |
| 5 | 多个GPS，不符合单接收器条件，暂停/重置 |
| 6 | 窗口容量损失，停止发布坐标 |
| 7 | 核心数值计算异常 |

版本3不发送旧协议状态2；显示器兼容识别2为有效状态，但不会突出积累时长。转向不清空历史；源GPS间隔大于10秒时仅开始新的窗口段，局部坐标原点保留至核心重置。容量为1024点，支持名义10Hz的完整90秒窗口。发生容量损失后报告无效，直到损失观测完全退出90秒范围或开始新段，不能悄悄以更短窗口继续发布。

飞控以2秒新鲜度为准停止发布新坐标，显示端5秒为缓存有效期上限。两者作用不同：若飞控主动无效状态到达，立即清空；如消息中断，缓存按原结果与源GPS年龄过期。重复快照不把旧估计当新计算，不完整新批次不能替旧结果续期。`ST_AGE`在显示端还会加上该批首包接收后的等待时间；从形成到首包到达的传输延迟没有硬件时钟同步测量，不应将它解释为精确端到端延迟。

显示有效结果至少要求同批版本、坐标、状态、GPS计数/源时间、快照序号、段号、窗口信息和必要权重诊断收齐。`ST_MSGMS/ST_MAXUS/ST_DT/ST_OVR`为附加诊断；缺失保留为空。原导航经纬度也仅在同批收齐时显示。迟到旧批不覆盖新批，冲突字段使该批失效。

## 机载日志

以下记录仅在编译启用日志且设备实际允许记录时写入；本模块不会自动修改`LOG_DISARMED`。需要机载逐历元记录时，可在Mission Planner完整参数列表中先保存设备原`LOG_DISARMED`值，再手工设为1并读取确认，核对SD卡后端已启用且存储可写。固定上游中值2会在USB连接时停止未解锁记录，值3可能在从未解锁的实验后重启时丢弃文件，因此USB定点采集应核对所选值。采集后下载并确认DataFlash中实际包含这些消息，结束后按需恢复原参数。完整电脑JSONL不能替代机载逐历元记录。

| 消息 | 触发 | 字段及含义 |
|---|---|---|
| `S3IM` | 单GPS、未解锁条件下的每次10Hz处理 | `TimeUS,GX,GY,GZ,Healthy`；实际读取的角速度rad/s与健康标志 |
| `S3PO` | 每次成功GPS更新 | `TimeUS,GPSms,MsgMS,RLat,RLon,Lat,Lon,E,N,Seq`；原GPS、自研坐标及局部位置；其中`Seq`为核心GPS更新计数，**不同于ST_SEQ快照序号** |
| `S3DG` | 同次成功GPS更新 | `TimeUS,Sig,Lam,Hub,Wgt,Neff,Span,NWin,Seg,US,MaxUS,Over`；权重、窗口、全局段、核心耗时及500μs超限次数 |
| `S3IN` | 同次成功GPS更新 | `TimeUS,GPSms,HAcc,HDop,NSat,Fix,IMU,State,Lost`；原质量字段、所用IMU状态、状态及累计容量损失数 |
| `S3ER` | 核心拒绝的GPS更新调用 | `TimeUS,GPSms,Result,Lost`；核心返回码及累计容量损失数，不冒充成功输出 |
| `S3TX` | 每次形成遥测快照 | `TimeUS,BatchMS,Seq,GPSms,DtMS,State,Fields`；快照时间、序号、源时间、周期、状态及计划发送字段数 |

`S3TX.Fields`是计划字段数，不是已成功送达的数量。各条记录可能受日志配置、后端空间和实际运行负载影响；没有记录不等于算法一定未计算，需要结合原GPS、遥测和设备日志状态判断。

`S3ER.Result`对应核心枚举：0成功、1重复、2逆序、3输入无效、4容量损失、5数值异常。适配层在调用核心前过滤重复源时间、fix不足、已解锁、多GPS及过期输入，这些早期过滤不会都产生S3ER。

## 验证范围

公开主机检查覆盖核心、真实适配器配合边界替身、合成同输入对齐、适配器实际输出到显示聚合器的协议检查和隐藏GUI构建。它们不连接飞控，不代表真实UART完整率或目标板耗时已经测得。用户完成固件构建后可查看本地生成的`release/firmware_manifest.json`；硬件启动、资源、转向及连续输出仍需按[验收说明](../docs/VALIDATION.md)实测。
