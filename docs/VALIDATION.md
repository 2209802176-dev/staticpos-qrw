# 验证与上机验收

## 公开软件检查

运行 `python tools/run_checks.py`。检查覆盖核心行为、GPS/IMU时间边界、90秒端点、质量未知值、转向保持、Huber异常输入、容量损失、断流恢复、时钟回绕、适配器真实代码与模拟设备、C++遥测到Python聚合器、中文界面有效与失效状态。

NumPy参考默认使用生成的合成输入。截断输入后的前缀应保持一致，以检查未来样本不会影响此前结果。普通构建与 `-fsingle-precision-constant` 构建的数值语义也应一致。生成的验证输出保存在本地并由Git忽略。

公开测试中的坐标为合成示例，不代表实验测点。测试不打开串口；通过主机检查不能代替飞控实测。

## 完整固件

使用固定上游与指定ARM工具链编译整个ArduCopter fmuv3目标，检查APJ board ID、模块标记、映像容量、ELF及源码校验清单。适配器替身编译不等于完整固件构建。

## 目标板验收

| 项目 | 应核对的现象 |
|---|---|
| 设备匹配 | 板型、单GPS、未解锁与固件V3标记 |
| 启动 | 有效GPS后开始输出，窗口未满时不等待 |
| 输入 | source fix时间单调，重复观测不增加计数 |
| 转向 | 对应门控倍率变化，窗口历史保留 |
| 遥测 | 实际批次间隔、完整率和源年龄符合记录，丢包不借用旧字段 |
| 失效 | 解锁、多GPS、过期与容量异常停止显示有效坐标 |
| 恢复 | 新的有效GPS使状态恢复，长间隔建立新段 |
| 资源 | 计算耗时、最长耗时、预约超限次数、内存与日志后端状态 |
| 记录 | CSV、消息JSONL、事件JSONL及所需机载消息确实生成 |

定位精度需要独立且正确复现的参考条件。保留全部有效历元及退化结果；平滑不等于绝对误差一定减小。用户自己的实验材料保持本地，不提交到本仓库或公开Issue。
