# 自研定位 V3 显示与采集

程序只显示飞控已经计算好的坐标和权重诊断。电脑不参与位置估计。界面显示原始 M8N GPS、原导航接口输出、自研 V3 坐标，以及 GPS 质量尺度、转向倍率、Huber 因子、最新观测权重、窗口支持数、计算时耗、源时间与实收批次周期。

在仓库根目录创建 Python 虚拟环境并安装 `requirements.txt`，然后运行 `启动显示器.cmd` 或 `python monitor/static_monitor.py`。Windows Python 安装时需要包含 Tcl/Tk。

先释放 Mission Planner 对相同 COM 端口的占用，手工列出和选择端口、波特率、系统 ID，再点击连接。支持 `COM5`、`udpin:127.0.0.1:14551` 和 `udpout:主机:端口`。程序不自动连接、不自动重连；飞控重启后应手工断开再连接。连接后只发送地面站心跳和 GPS 5 Hz、ATTITUDE 10 Hz、RAW_IMU 10 Hz 的消息周期请求；实际接收率由设备与链路决定，所有请求及 ACK 记录在日志中。

每次手工连接在仓库根目录 `monitor_logs/` 新建三个同名文件：

- `.csv`：每秒显示快照，包含 UTC、单调接收时钟、GPS 源时间、结果序号、批次时间和诊断。快照会重复已有结果，不是独立 GPS 历元。
- `.messages.jsonl`：逐条保存允许的原始 GPS、IMU、姿态、V3 字段、心跳、ACK、状态及原导航消息，保留消息自身时钟与本机接收时钟。
- `.events.jsonl`：保存连接、消息速率请求、错误、关闭与自由文本操作标记。可标记转向开始和结束。

固件的 `ST_VER` 必须为 3。聚合器按完全相同的 `time_boot_ms` 组包，不跨批次拼接。有效批次需要所有基础坐标、状态、版本与诊断字段；`ST_FCOK=1` 且同批原导航经纬度完整合法时才显示原导航坐标。原导航接口有效不表示已通过完整 EKF 健康认证。

新批次尚未收齐时，保留上一完整结果及其原年龄。主动无效状态、字段冲突或固件版本不符立即清空。`ST_SEQ` 是遥测快照序号，`ST_COUNT` 是算法接受的 GPS 更新数，`ST_GPSMS` 是该估计对应的 GPS 源时刻。新的遥测快照可以再次发布同一个估计；重复消息、重复快照序号或重复源时间不会延长该估计的接收有效期。GPS 数据年龄与本批次的本机等待时间相加超过 5 秒、同一估计超过 5 秒未更新时清空坐标及对应诊断。两种年龄分别检查，不相加。5 秒是显示缓存上限，固件可更早主动报告无效；它不表示飞控又计算了一个新结果。输出有效也不表示达到某一精度。

可选诊断 `ST_MSGMS` 记录原始消息到达飞控的毫秒时刻，按 uint32 位模式还原；`ST_MAXUS` 是至今观测到的最长计算时耗，`ST_OVR` 是超过初始 500μs 调度预约预算的累计次数（不是已认证的硬件时耗上限），`ST_DT` 是相邻飞控快照捕获的间隔。显示端另行测量并显示 `batch_interval_s`，即相邻完整快照第一包的本机实收间隔。这些时钟用于区分算法更新、快照调度和传输延迟。

局部东/北偏移相对于首个有效 GPS 建立的原点，不是 RTK 真值误差。质量尺度是算法经验权重尺度，权重支持数不是独立样本数。界面提供这些数值用于理解本次计算与排查通信，不给出精度置信区间。

离线检查（不连接设备、不创建采集日志）：

```powershell
python monitor/static_monitor.py --self-test
python monitor/static_monitor.py --smoke-gui
python tools/validate_monitor.py --gui
```

`--smoke-gui` 创建隐藏窗口并处理定时刷新后退出。`--list-ports` 仅列举端口，不打开设备。

`tools/validate_monitor.py --gui` 还检查有效/失效坐标和诊断的 GUI 渲染，并在本地 `runtime/monitor_validation.json` 写入检查结果与源码哈希。完整主机检查编译实际 C++ 适配器后，`tests/test_adapter_protocol.py` 会把它生成的模拟遥测逐包送入本聚合器，覆盖 5 Hz 输入、1 Hz 分批快照、中断、恢复、解锁失效与新段；这个检查没有物理硬件参与。
