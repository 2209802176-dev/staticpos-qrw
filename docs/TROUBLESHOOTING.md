# 故障排查

先区分算法输入、飞控计算、遥测发送和电脑显示四个环节。保留版本号、源时间与有效状态，可以避免把缓存显示误当成新的算法结果。

## 主机检查或启动失败

| 现象 | 检查与处理 |
| --- | --- |
| 找不到 Python | 使用 Python 3.11+；Windows 可用 `py -3`，或直接使用仓库 `.venv/Scripts/python.exe` |
| 找不到 `g++` | 安装适合当前操作系统的 GCC，通过 `CXX` 指定可执行文件；确认它能在当前终端启动 |
| Windows 测试程序提示缺少 DLL | 确保所选编译器的运行库可找到；`tools/run_checks.py` 会把编译器所在目录加入子进程 PATH |
| `tkinter` 无法导入 | 安装当前 Python 对应的 Tcl/Tk；虚拟环境依赖安装不能替代系统 Tcl/Tk |
| Linux 没有显示会话 | 用 `--skip-gui` 检查无界面部分，或配置 Xvfb 后执行完整检查 |
| 缺少 NumPy、pymavlink 或 serial | 使用运行程序的同一个 Python 执行 `-m pip install -r requirements.txt` |

完整检查入口是 `python tools/run_checks.py`。单独运行 `tests/test_adapter_protocol.py` 前需要先编译适配器测试程序；完整入口会按正确顺序完成。

## 固件构建失败

| 现象 | 检查与处理 |
| --- | --- |
| 上游提交或调度布局不匹配 | 核对固定提交，不绕过安装脚本的断言；见 [构建指南](BUILDING.md) |
| bootstrap 提示目标目录已存在 | 它不会覆盖已有 checkout。先核对目录用途与 HEAD，再决定使用已有目录或另建干净的仓库副本 |
| 子模块或 Python 构建包缺失 | 完成上游子模块初始化，并安装 `requirements-build.txt` 与系统构建前提 |
| 找不到 Arm 编译器 | 检查 `arm-none-eabi-g++ --version`，设置 `ARM_TOOLCHAIN_BIN` 指向选定工具链的 `bin` |
| WSL 无法启动 | 先使本机 Linux/WSL 环境正常工作，再运行项目构建脚本；主机软件检查可单独执行 |
| 固件与清单哈希不一致 | 停止混用文件；根据同一源版本重新构建和生成清单 |

本地构建与检查输出放在 `runtime/`。报告问题时提供失败阶段与最小日志片段即可，不需要上传整个工具链或本机目录。

## 连接成功但没有自研坐标

1. 确认其他软件已释放同一 COM 端口，波特率和系统 ID 与设备一致。UDP 需要已配置好的转发链路。
2. 查看是否收到飞控心跳、原始 GPS 和 `ST_VER=3`。V2 固件的字段不会被当作完整 V3 批次。
3. 核对未解锁、只有一个 GPS、至少 3D fix，以及坐标和源时间合法。
4. 查看 `ST_STATE`。等待 GPS、数据过期、解锁、多 GPS、窗口容量不足和数值计算异常都会停止显示有效自研坐标。
5. 查看 `.messages.jsonl` 是否存在同一 `time_boot_ms` 的完整必需字段。缺包不会用旧批次字段拼补。

单个有效 GPS 就能开始输出；无需等待 90 秒或 300 秒。窗口逐渐填充，也不等于精度已经收敛。

## 坐标间歇消失或显示年龄较大

检查实际 `batch_interval_s`、`ST_DT`、`ST_GPSMS`、`ST_MSGMS` 和 `ST_AGE`：

- `ST_DT` 是飞控快照捕获间隔；`batch_interval_s` 是电脑收到相邻完整批次第一包的间隔。
- 新批次未收齐时，上一完整结果只保留到它原来的有效期。
- 主动无效状态立即清空；显示缓存上限为 5 秒。
- 新快照序号可以重复发布同一 GPS 结果；它不会变成新的定位历元。
- 重复包、不完整包和迟到旧包不会给结果续期。

低波特率或繁忙链路可能不足以传送全部诊断。优先检查设备原配置和实际接收日志；不要单靠延长缓存来掩盖新数据未到达。1 Hz 是需要用实机确认的批次目标。

## 原始 GPS、原导航和自研结果不同

这是三个不同的数据接口。先核对源时刻、定位状态和健康信息，再比较坐标。`ST_FCOK=1` 只表示原导航接口返回位置，不是完整 EKF 健康认证。

自研 E/N 相对首个有效 GPS 建立的局部原点，不能直接当作 RTK 误差。点云更集中也不保证平均位置更靠近真值。90 秒记忆可能延迟对持续变化的响应；单接收机自身信息不能保证消除共同偏差或区分真实平移。

转向时下降为四分之一的是门控项。最终权重还受 GPS 质量尺度和 Huber 残差影响，因此综合权重未必恰好变化四倍。

## 重启、时间回退或窗口容量异常

飞控重启后手工断开再连接，建立新的接收会话。源时间、快照序号或段号回退会受到聚合器保护，不能靠反复发送旧包恢复有效显示。

核心固定容量为 1024 点，90 秒窗口包含两端点。高于算法更新能力的输入率或容量不足需要调整工程配置并重新验证；程序会显式报告失效，不能把静默截断后的较短窗口说成原来的90秒算法。

## 提交可复现问题

使用仓库的 [问题报告表单](https://github.com/2209802176-dev/staticpos-qrw/issues/new/choose)，提供代码提交、主机/板型、命令、输入率、连接方式、期望与实际行为。优先提供可公开的合成输入与最小日志片段。公开前移除真实经纬度、设备标识和凭据；示例 `10°N, 20°E` 是合成占位，不是项目测点。

涉及可利用的安全问题时按 [SECURITY.md](../SECURITY.md) 处理，不在公开 Issue 中放漏洞细节。
